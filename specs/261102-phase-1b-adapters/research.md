# Research: Phase 1b shared adapters

**Date:** 2026-11-02 · **Source PRD:** [phase-1b-adapters-PRD.md](./phase-1b-adapters-PRD.md)

## Research questions

1. How are the first board user created and a pairing challenge approved against a fresh authenticated server in CI (Better Auth sign-up route and body, bootstrap_pending handling, `/cli-auth/challenges/:id/approve` and the session cookie it needs)? Read server/src and record the exact requests.
2. What are the exact request and response bodies (including error bodies and status codes) of every endpoint the gateway ports use? Record per endpoint with file:line, starting from the Phase 1a research answers.
3. Which SQLDelight and Ktor versions are compatible with Kotlin 2.4.21 and the Android KMP library plugin 9.5.0? Check the catalog candidates before adding them.
4. What does Ktor's Darwin engine surface for TLS and certificate failures, and how can they be mapped to `CertificateInvalid` testably on the simulator (self-signed loopback stub)?
5. Which Security.framework and LocalAuthentication APIs are callable from Kotlin/Native without cinterop definitions, and what does Keychain behave like on the simulator (accessibility, biometry access control)?
6. Can the Phase 1a fakes' behaviors (decide-then-poll, cursor paging, approval state machine) be reproduced by a MockEngine server stub without re-implementing the server, to run the contract suites against real adapters?

## Answers: milestone 1b-1 (client, errors, health, auth)

Server paths are relative to `~/Code/Test/paperclip` (the pinned 2026.1023.0 source).

**Q3 Versions (ANSWERED, verified by building).** Maven Central metadata (2026-11-02): Ktor `3.6.1` (latest, published against Kotlin 2.3.21, `ktor-client-darwin-3.6.1-kotlin-tooling-metadata.json`), kotlinx-serialization-json `1.12.0` (built with Kotlin 2.4.10), plugin `org.jetbrains.kotlin.plugin.serialization:2.4.21` exists. SQLDelight latest is `2.4.1` (added to the catalog in 1b-2, with its module). A spike with `ktor-client-core` + `ktor-client-mock` compiled and ran green on `jvmTest`, `testAndroidHostTest` and `iosSimulatorArm64Test` under Kotlin 2.4.21 and AGP 9.5.0 with `allWarningsAsErrors`.

**Q2 `GET /api/health`** (`server/src/routes/health.ts`). Unauthenticated caller of an `authenticated` server: 200 redacted body `{status: "ok"|"starting", deploymentMode, deploymentExposure, localAiLoginSupported, commit, bootstrapStatus: "ready"|"bootstrap_pending", bootstrapInviteActive, ...}` (lines 394-418), no `version`. `local_trusted` or an authenticated caller gets `version`/`serverVersion` too (lines 421-448). Database down: 503 `{status:"unhealthy", version, serverVersion, commit, error:"database_unreachable"}` (lines 318-330), no `deploymentMode`. No-db branch (lines 270-290) omits `deploymentExposure`. Mapping: status string -> `ServerStatus`, absent mode -> `Unknown` (refused, fail closed), `version ?: serverVersion` -> `serverVersion`.

**Q2 Pairing** (`server/src/routes/access.ts`). `POST /api/cli-auth/challenges` (2786-2808): body validated by `createCliAuthChallengeSchema` (`packages/shared/src/validators/access.ts:73-78`): `command` REQUIRED 1-240 chars, `clientName` <=120, `requestedAccess` default `board`, `requestedCompanyId` guid; 201 `{id, token, boardApiToken, approvalPath, approvalUrl|null, pollPath, expiresAt, suggestedPollIntervalMs}`. `approvalUrl` is null when the server cannot derive its own origin, so the client builds `baseUri + approvalPath` (a web path, not under `/api`). Rate limited with 429 and `Retry-After` (2690-2698). `GET /api/cli-auth/challenges/:id?token=` (2810-2838): non-UUID id -> 400 `Invalid CLI auth challenge ID`, unknown id or wrong token -> 404 `CLI auth challenge not found`, else 200 `{id,status,...,expiresAt}`; `status` is one of `pending|approved|cancelled|expired` (`board-auth.ts:49-54`). Approve (2842) and cancel (2872) take `{token}` and need a browser session, so the app never calls them; the stub emulates them for `approveInBrowser`.
**Q2 Account.** `GET /api/cli-auth/me` (2885-2898): 200 `{user:{id,name,email}|null, userId, isInstanceAdmin, companyIds, memberships:[{companyId,membershipRole,status}], source, keyId|null}`; 401 `Board authentication required` otherwise. `GET /api/board-api-keys` (2901): 200 array `{id,name,createdAt,lastUsedAt,revokedAt,expiresAt}` (`board-auth.ts:247-274`; active only unless `includeInactive=true`). `POST /api/board-api-keys` (2912): creates a named key; not used by the app (pairing is the only way a device gets a key). `DELETE /api/board-api-keys/:keyId` (2954): non-UUID -> 400 `Invalid board API key ID`, not the caller's -> 404 `Board API key not found`, else 200 `{ok:true,keyId}`. `POST /api/cli-auth/revoke-current` (2970): 400 `Current board API key context is required` unless the actor is a board key, else 200 `{revoked:true,keyId}`. `GET /api/companies?scope=accessible` (`server/src/routes/companies.ts:380-400`): 200 array of companies (`id`, `name`, ...); any other `scope` -> 400.

**Q2 Errors.** Every thrown `HttpError` becomes `{error: message, details?, code?...}` with the error's status (`server/src/middleware/error-handler.ts:157-215`); `HttpError` helpers in `server/src/errors.ts:1-60`: 400, 401, 403, 404, 409, 413, 415, 422, 429. Zod failures -> 400 `{error:"Validation error", details:[...]}` (225-232); malformed JSON -> 400 `{error:"Invalid JSON body"}` (236-243); crashes -> 500 `{error:"Internal server error"}`; shutdown -> 503. Secret-sensitive routes (cli-auth, board keys) replace 5xx bodies with `{error:"Internal server error"}` (205-215). Routes: health 200/503; create challenge 201/400/429; poll 200/400/404/429; me 200/401; keys list 200/401; revoke key 200/400/401/404; revoke-current 200/400/401; companies 200/400/401/403.

**Q4 Darwin engine** (`ktor-client-darwin-3.6.1-sources.jar`, read from Maven Central). `TimeoutUtils.kt:29` maps `NSURLErrorTimedOut` to Ktor's `SocketTimeoutException`; every other NSError is `DarwinHttpRequestException(origin: NSError)` (`DarwinUtils.kt:132`), so TLS failures arrive as NSURLErrorDomain codes -1200 to -1206 (secure connection failed, certificate bad date, untrusted, unknown root, not yet valid, client certificate rejected or required) and -1022 (ATS). `classifyUrlError` maps those to `CertificateInvalid`; everything else, including -1004, -1003, -1009, -1005, to `Unreachable`. Tested in `iosTest` against real `NSError` values wrapped in `DarwinHttpRequestException`. A live self-signed loopback test is NOT done in 1b-1 (needs a TLS stub server on the simulator); it moves to 1b-5 with the Swift loopback test. Darwin also ships `certificates/CertificatePinner` (SPKI sha256 pins per host pattern, `handleChallenge`), the building block for AD-005 enforcement (see ADR-040).
**JVM/OkHttp:** `javax.net.ssl.SSLException` (handshake, peer unverified, hostname) -> `CertificateInvalid`; `ConnectException`, `UnknownHostException`, `NoRouteToHostException`, `SocketException` -> `Unreachable`; `java.net.SocketTimeoutException` -> `Timeout`.

**Q6 Contract suites on real adapters.** Suites in `shared/testing/.../contract` are abstract classes with `create()` plus scenario hooks (`approveInBrowser`, `letExpire`, addresses); `Fake*ContractTest` subclasses in `shared/testing/src/commonTest/.../FakeGatewayContractTest.kt` implement them and call `runAll()` inside `runTest`. The real-adapter subclasses live in `shared/infrastructure/api/src/commonTest` and implement the same hooks on `StubPaperclipServer`.

**Ktor facts the design relies on.** `HttpRequestTimeoutException`, `ConnectTimeoutException`, `SocketTimeoutException` are `kotlinx.io.IOException`s whose messages contain the request URL (the poll URL carries the challenge token), so no exception message is ever copied. The `Auth` plugin caches tokens and re-sends after a 401, and `HttpRequestRetry` would replay mutations; neither is installed. Redirects are not followed (a redirected request would carry the bearer to another host).
**Test fixtures on Kotlin/Native.** `commonTest/resources` files cannot be read from a Kotlin/Native test (no classpath), so server bodies are Kotlin raw strings in `ServerFixtures` (deviation from "fixtures under src/commonTest/resources", ADR-041).


## Answers: milestone 1b-2 (SQLDelight persistence)

**Q3 SQLDelight 2.4.1 with Kotlin 2.4.21 and AGP 9.5.0 (ANSWERED, verified by a spike that ran, not only compiled).** Maven Central metadata lists `app.cash.sqldelight:gradle-plugin` 2.4.1 as latest (2026-10-06). The plugin (`app.cash.sqldelight`, catalog alias `sqldelight`, declared `apply false` at the root like the other plugins) was applied in `shared/infrastructure/persistence/build.gradle.kts` after `pafm.kmp-library` (Kotlin Multiplatform plus `com.android.kotlin.multiplatform.library`) with no `kotlin.mpp` property or other setting. Generated code goes to `build/generated/sqldelight/code/PaperclipDatabase/commonMain`. Dependencies: `runtime`, `coroutines-extensions` (common), `native-driver` (iosMain), `android-driver` (androidMain), `sqlite-driver` (jvmMain and, for the Android host test, `androidHostTest`). A one-table spike test ran green on `jvmTest`, `testAndroidHostTest` and `iosSimulatorArm64Test`; the Kotlin/Native iOS test binary linked sqlite3 with no linker flag (the PaperclipKit framework that Xcode links is not yet checked: verify sqlite3 linkage when `umbrella` depends on `persistence`, 1b-5). `allWarningsAsErrors` stays on. The Android host test cannot use `android-driver` (framework SQLite classes are stubs on the host JVM), so it runs the JDBC driver; the Android factory is compile-checked only.

**Generated code and the gates.** Spotless (`exclude("**/build/**")`), detekt (`source` globs `shared/**/src/**` and `exclude("**/build/**")`, root `build.gradle.kts`) and Android Lint do not see `build/generated`; `./gradlew check lint` was green with generated classes present, so no exclusion commit was needed.

**Mapping to columns.** `Instance` -> `instance_config`, one column per field (no secret field exists): ids and text as TEXT, `Instant` as ISO-8601 TEXT (nanoseconds survive; epoch millis would not), enums by name, `pins` as space separated digests (a digest is base64 with no space), `sortOrder` INTEGER, index on `sort_order`. `AppSettings` -> single row `app_settings` (`id = 1` by CHECK). `AttentionFeed` -> one row of `attention_cache` per (instance, company) holding a JSON payload; normalising was rejected because the feed has 13 detail variants and nested optional records that the Inbox always reads whole. Payload classes are persistence-internal (domain stays annotation free).

**Versioning and migrations.** SQLDelight numbers the schema by `.sqm` files: `N.sqm` migrates N to N+1 and the current version is the number of `.sqm` files plus 1. `schemaOutputDirectory` makes `generateCommonMainPaperclipDatabaseSchema` write `<version>.db`; both `1.db` and `2.db` are committed and `verifyCommonMainPaperclipDatabaseMigration` (in the `check` graph) fails if the `.sq` files and the migrations drift from a snapshot. A migration is tested at runtime by building version 1 from hand-written DDL, calling `PaperclipDatabase.Schema.migrate(driver, 1, Schema.version)` and reading through the adapters (`MigrationTest`, three targets). Version 2 (`attention_cache.format`) exists to exercise this path before any release. The JDBC driver keeps no version, so `prepareSchema` maintains `PRAGMA user_version`; the native and Android drivers do it themselves from the schema.

**Where the iOS file lives and backup.** Application Support (`NSSearchPathForDirectoriesInDomains(NSApplicationSupportDirectory...)`, e.g. `.../data/Library/Application Support` on the simulator) in the folder `PaperclipData`; Caches can be purged and Documents is user visible. `NSURLIsExcludedFromBackupKey` is set on the folder and on each database file, read back through `resourceValuesForKeys` in `IosPersistenceTest`, also after recreation. File protection `NSFileProtectionCompleteUntilFirstUserAuthentication` is requested on the folder and files; the simulator returns no `NSFileProtectionKey` attribute, so that part is not verifiable here. The default base path of the native driver was not locatable from a Kotlin/Native test host, so the path is always explicit. On Android the helper is configured with `noBackupDirectory(true)` (`noBackupFilesDir`, not part of Auto Backup).

**Concurrency finding.** `JdbcSqliteDriver(IN_MEMORY)` shares one connection across threads and a parallel transaction fails with `cannot start a transaction within a transaction` (reproduced by `ConcurrencyTest` before the fix). All ports of one database run on one `limitedParallelism(1)` dispatcher (ADR-043).

**Corruption.** SQLite opens a garbage file without complaint; the first statement fails (JDBC: `file is not a database`). A 0-byte file is a valid empty database. A file with a newer `user_version`: on iOS the native driver (SQLiter) leaves the higher version in place when it opens the file, so the probe rejects it (`IosPersistenceTest`, written with a throwaway newer-schema driver; the driver is lazy, only a first statement writes the version); on Android `SupportSQLiteOpenHelper.onDowngrade` throws by default (documented behaviour, not run here); JDBC has no version handling of its own. Recovery = probe after open (`user_version` not newer than the code, the three tables exist), else delete the database and its `-wal`/`-shm`/`-journal` and open again (ADR-042).

## Answers: milestone 1b-3 (device services)

**Q5a Can a Kotlin/Native test use the Keychain? NO (measured 2026-11-02, Xcode 26, iPhone 17 simulator).** A spike test called `SecItemAdd` (generic password, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`): standalone `iosSimulatorArm64Test` (default `simctl spawn --standalone`): status -25291 (`errSecNotAvailable`); forced onto the booted simulator (`standalone = false`): -34018 (`errSecMissingEntitlement`); the same binary re-signed with a `keychain-access-groups` entitlement is refused by `simctl spawn` ("Security policy issue", code 163). A Swift Testing test inside the app test host: -34018 with `CODE_SIGNING_ALLOWED=NO` (what `ios-test.sh` had), 0 with `CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=YES`. Decision: ADR-050 (Keychain tests in the app test host through `PlatformServices`; `ios-test.sh` signs ad hoc).

**Q5b LocalAuthentication on a simulator (measured).** In the app test host, `canEvaluatePolicy(.deviceOwnerAuthentication)` is true (no `LAError`; the simulator reports a passcode), so a real `evaluatePolicy` shows a prompt and waits for a person (one attempt waited 320 s for the system timeout). `.deviceOwnerAuthenticationWithBiometrics` gives `can=false`, domain `com.apple.LocalAuthentication`, code -7 (`biometryNotEnrolled`). Cancelling the Swift task invalidates the context and ends the call in about 0.5 s without an approval. In a bare Kotlin/Native test binary the call fails with an NSError outside `LAErrorDomain` (4099, XPC connection to the daemon invalidated), mapped to Unavailable. So `passcodeNotSet` (-5) and lockout cannot be produced live on this simulator: they are asserted through the injectable authenticator with the real `LAError*` constants. Mapping: ADR-052.

**Q5c NWPathMonitor from Kotlin/Native.** `platform.Network` exposes the C API: `nw_path_monitor_create`, `nw_path_monitor_set_queue` (with `dispatch_queue_create`), `nw_path_monitor_set_update_handler` (a Kotlin lambda), `nw_path_monitor_start`, `nw_path_get_status == nw_path_status_satisfied`, `nw_path_monitor_cancel`. The handler runs on the monitor's serial queue and writes a `MutableStateFlow`, which is thread-safe. A real monitor delivered its first path inside the bare test binary within the 5 s limit (`NwConnectivityTest`), so no daemon problem there. The first path arrives shortly after start, so the value is optimistic (online) until then.

**Q5d Device time zone.** kotlinx-datetime 0.7.1 `TimeZone.currentSystemDefault()` on Darwin calls `NSTimeZone.resetSystemTimeZone` then reads `NSTimeZone.systemTimeZone.name` on every call (`commonMain/TimeZone.kt` KDoc lines 75-76 of the iosarm64 sources jar), so a zone change while the app runs is picked up; no custom actual is needed. `DeviceTimeZoneContract` passes on JVM, Android host and iOS.

**Other facts learned.** Open Keychain items also report an `accc` access control (`<SecAccessControlRef: aku>`); a protected one lists a constraint (`cbio` biometry current set, `cpo` user presence), which is how the tests tell them apart. On the simulator a `.biometryCurrentSet` item is accepted with no biometrics enrolled (`SecItemAdd` succeeds, `accc` shows `cbio`); a device without biometrics falls back to `.userPresence` inside the store (tested with a scripted backend only). Kotlin/Native test names may not contain commas. `CFBridgingRetain`/`CFBridgingRelease` live in `platform.Foundation`.

**Corrections found (each has a failing test first, then a fix).**

1. **JSON numbers in exponent form.** `amountObserved` and `agents.spentMonthlyCents` are `numeric(24,7)` columns read with `mode: "number"` (`db/dist/schema/budget_incidents.js:18`, `agents.js:27`); the dashboard `monthSpendCents` and the window-spend `costCents` are `::double precision` sums (`services/dashboard.js:88`, `services/costs.js:23-25,516`). `JSON.stringify` prints a number below 1e-6 as `5e-7`, which `ceilToCents` called Malformed (the 1b-4a test even pinned `1e3` as refused). Fixed: `ceilToCents` reads `e`/`E` literals with string arithmetic (test `BudgetMapperTest`, commit c762ed9). The window-spend rows also carry `costCentsExact`, an exact text (`services/costs.js:531`, `shared/dist/money.js:36`), which the new mapper prefers.
2. **A malformed id is a 500, not a 404.** `eq(decisions.id, id)`, `eq(budgetIncidents.id, id)` and the approval `router.param("id")` query run against `uuid` columns with no guard (`services/decisions.js:243`, `services/budgets.js:697-705`, `routes/approvals.js:30-58`, `services/authorization.js:2147`), so a non-uuid id answers `500 {"error":"Internal server error"}` (`middleware/error-handler.js:215`). The 1b-4a stub answered 404. Fixed in the stub (`PinnedStubFidelityTest`); the adapters already refuse non-uuid ids locally (ADR-057). Incident ids in the 1b-4a tests became uuids.
3. **Attention `limit`.** A non-integer limit is `400 limit must be an integer` (`routes/attention.js:36-39`) and an out-of-range one `400 limit must be an integer between 1 and 100` (`services/attention.js:1565-1568`). The stub fell back to 50 for `abc`. Fixed in the stub.
4. **Triage snooze and calendar dates.** A triage `snoozedUntil` in the future hides the card from the feed (`services/attention.js:1536`), more than five years ahead is `422 snoozedUntil must be within five years` (`services/decision-queues.js:485-487`), and `decideBy` must be a real calendar date (`shared/dist/validators/decision-queue.js:28-31`; `2026-02-31` is 400). The stub ignored all three. Fixed in the stub.
5. **The desk badge.** `deskBadgeCount` counts items that are new today or whose `decideBy` is due: `today`, a date on or before today, or `this_week` only when today is Sunday (`services/attention.js:297-335,1624`). The stub counted `decideBy == "today"` only. Fixed in the stub. The adapter was never affected: it reads the server's number.
6. **Approval payloads are redacted** by `redactEventPayload` (`routes/approvals.js:13-17`, `redaction.js:2-6,366`): keys that look like secrets or commands become the string `***REDACTED***`. The 1b-4a approval mapper already treats a field of another type as absent (ADR-055), so no change; noted here because the 1b-4a research said the payload fields were read from the UI source.
