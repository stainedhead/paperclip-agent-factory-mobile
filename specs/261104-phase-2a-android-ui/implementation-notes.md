# Implementation notes: Phase 2a Android UI

**Date:** 2026-11-04

Record decisions, edge cases, deviations and lessons as the work lands, with commit hashes. Update after every task (same rule as `status.md`).

## Technical decisions

- **Research Q5 resolved (T0.1/T0.2): AGP 9.5.0 built-in Kotlin needs no extra Kotlin plugin.** `:androidApp` applies only `com.android.application` (through the `pafm.android-app` convention plugin in `build-logic`) plus `org.jetbrains.kotlin.plugin.compose`; `src/main/kotlin` is compiled by AGP's built-in Kotlin (task `compileDebugKotlin`, output under `build/intermediates/built_in_kotlinc`). `org.jetbrains.kotlin.android` is not applied. The Compose compiler plugin does require the Compose runtime on the classpath (the build failed with `IncompatibleComposeRuntimeVersionException` until `compose-runtime` was added), so the module depends on the BOM and the runtime from the start.
- SDK constants (`compileSdk` 37, `minSdk` 28, namespace root) live in `build-logic/src/main/kotlin/PafmAndroid.kt` and are used by both `pafm.kmp-library` and `pafm.android-app` (T0.1 refactor step). `targetSdk` equals `compileSdk`.
- **Catalog (T0.2).** Latest stable versions that resolve (checked by resolving every entry in a throwaway configuration, 141 artifacts): Compose BOM 2026.09.00; activity-compose 1.13.0; navigation-compose 2.10.2; lifecycle (viewmodel/runtime-compose, process) 2.11.0; biometric 1.1.0 (1.4.0-alpha07 exists, alpha not taken); browser 1.10.0; core-splashscreen 1.2.0; core-ktx 1.19.1; profileinstaller 1.4.1; androidx.test runner 1.7.0, core 1.7.0, ext-junit 1.3.0; Roborazzi 1.77.0; Robolectric 4.17; JUnit 4.13.2; junit-vintage-engine 6.1.3 (same version as the pinned `junit` 6.1.3, so a Vintage engine exists for the pinned JUnit platform: research Q6 sub-question answered). `CatalogRulesTest` (Konsist) fails on any literal dependency or plugin version in a `*.gradle.kts` (settings foojay plugin excepted).
- **Research Q2 resolved (T0.7): `withDeviceTest` DSL.** In `pafm.kmp-library`, inside `extensions.configure<KotlinMultiplatformAndroidLibraryTarget>("android") { ... }`: `withDeviceTest { instrumentationRunner = "androidx.test.runner.AndroidJUnitRunner" }`. It creates the source set `androidDeviceTest` and the tasks `assembleAndroidDeviceTest` and `connectedAndroidDeviceTest`. The convention enables it only for modules that have `src/androidDeviceTest` (securestore, platform, persistence, umbrella), so the other modules gain no variant. Dependencies are added with `sourceSets.matching { it.name == "androidDeviceTest" }.configureEach { dependencies { ... } }`: kotlin-test, androidx.test runner/core/ext-junit, coroutines-test. `check` has no `connected*` task in its graph (verified with `./gradlew check lint --dry-run`).
- **Device test method names cannot contain spaces.** D8 rejects backticked names with spaces for minSdk 28 (DEX 039: "Space characters in SimpleName ... not allowed prior to DEX version 040"), so device and instrumented tests use camelCase names; `commonTest`, host tests and JVM tests keep sentence names. Applies to `androidApp/src/androidTest` too.
- **Research Q6 resolved (T0.8), ADR-121.** JUnit Vintage engine 6.1.3 exists for the pinned JUnit 6.1.3 platform and works: `PureJvmSmokeTest` (JUnit 5), `ComposeSmokeTest` and `RoborazziSmokeTest` (JUnit 4 + Robolectric, `createComposeRule`) all run in one `:androidApp:testDebugUnitTest` (3 tests, 0 failures). The fallback (JUnit 4 throughout) is not needed. Needed to make Robolectric run: `--add-opens=java.base/java.io=ALL-UNNAMED` and `--add-exports=java.base/jdk.internal.access=ALL-UNNAMED` on the test JVM; `robolectric.properties` `sdk=36` (Robolectric 4.17 has no API 37 android-all, failing with `NoSuchMethodException InputManager.getInstance()`); compose-ui and compose-foundation as app (not test-only) dependencies (else `NoClassDefFoundError androidx/customview/poolingcontainer/R$id`). Roborazzi: `verifyRoborazziDebug` with no baseline fails ("original file ... was not found"), `recordRoborazziDebug` writes `src/test/screenshots/smoke.png`, `verifyRoborazziDebug` then passes.
- **Research Q (undecryptable record) resolved (T1.1, T1.2), ADR-123.** A record that does not decrypt under a healthy key, a missing key, a truncated or foreign file all read as `Missing`; only `KeyPermanentlyInvalidatedException` is `Invalidated`; any other Keystore failure is `Denied`. Verified on the host with `FakeKeystoreBackend` and on the Pixel 9 Pro emulator (flipped and truncated bytes, key deleted).
- **Protected keys use a 5 second authorization window, not per-use (T1.2).** `setUserAuthenticationParameters(5, STRONG | CREDENTIAL)` (API 30+) with the store asking the injected authenticator first; per-use needs a `CryptoObject` bound to the prompt and would put the activity inside `securestore`. Below API 30 a protected write fails (no deprecated API, no fallback to unprotected).
- **`KeystoreSecretStore(context, authenticate, writeReason)`** takes the prompt as `suspend (String) -> BiometricResult`; 2a-2 wires it to `BiometricPromptBiometrics` (a small adapter in the umbrella). `BiometricPromptBiometrics` takes `ReasonTexts` (moved from iosMain to commonMain), so the prompt title is the app's localized text.
- **Emulator facts (T1.2, T1.4).** `svc`/`cmd connectivity airplane-mode enable|disable` from `UiAutomation.executeShellCommand` flips the default network and the callback reports it within a second or two; the library test APK needs its own `src/androidDeviceTest/AndroidManifest.xml` for `ACCESS_NETWORK_STATE`. Removing the lock screen (`adb shell locksettings clear --old 1234`) deletes user-authentication keys on this emulator (API 37) rather than invalidating them. The two-phase run is `KeystoreInvalidationDeviceTest` with `-e invalidationPhase 1|2` through `adb shell am instrument` (set PIN, phase 1, clear PIN, phase 2).
- **Manifest rule (T1.3).** `androidx.biometric` 1.1.0 adds `USE_FINGERPRINT`: removed with `tools:node="remove"` (minSdk 28). `androidx.profileinstaller`'s exported `ProfileInstallReceiver` (from Compose; the rule was already red at the start of 2a-1) removed; `androidx.activity.ComponentActivity` from `ui-test-manifest` allowed in the debug manifest only. T8.6 re-adds the receiver for the benchmark build type in review.

## 2a-5 notes

- **Inbox holder.** The Inbox screen renders `GraphSession.inbox` (the session owns the holder, the badge and the refresh session, as the iPhone `AppEnvironment` does); it is never closed or refreshed on a timer by the screen. Deviation from the brief ("refresh session start/stop with the screen lifecycle"): that rule is for the detail screens (`RefreshWhileVisible`); the Inbox keeps the session's refresh so the tab badge stays current while another tab is shown. ADR-128.
- **Decision hints** travel on `AppRoute.Decision` (ADR-128), not in an in-memory table.
- **Budget sheet holder** lives in a sheet-scoped `ViewModelStore` (`WithSheetHolders`); the Inbox refreshes when the sheet closes.
- **Proof gaps in shared (not changed):** `DemoControls` exposes only `biometricPromptCount`; the fakes' `decide`, `approve`, `reject` and `resolve` call counters are not reachable from the app, so "zero decide calls after a declined prompt" is proven by the prompt count plus the screen (no execution, no final card, options still shown) and "decide called" by the execution results. The demo has no Viewer membership (Acme is Owner, Side Project is Operator, and Side Project has no cards), so viewer variants are rendered from states built in the test. No source for "switch factory" from the Inbox header: the iPhone `FactorySwitcher` line is not ported (the Factories tab does it); `onSignInAgain` of a detail screen error banner is not wired for the same reason (Retry is shown).
- **Process.** Tests were written with each screen and run red at least once by mutation or compile failure (a changed expectation failed; unresolved symbols failed the compile first), but for Decision, Approval and Budget the screen code was written before its tests in the same task, not strictly red first.
- **Pitfalls found.** Robolectric `createComposeRule` allows one `setContent` per test (use a state to change what is shown); a node with a test tag hides the tags of its merged children (use `useUnmergedTree` for a lock glyph); `ScreenHolder`'s trailing lambda is the in-flight check, so new parameters go before it; baselines that read dates need a fixed time zone (the screenshot test pins UTC) and the shell baselines need the demo clock (`LocalReferenceMillis`) or "Updated 6h ago" moves with the day; compound shell commands and heredocs with `$` are refused in this sandbox (use the Edit and Write tools).

## 2a-6 notes

- **Process (red first).** Every task started with its tests and a stub that compiled and rendered nothing (or threw `TODO()` for label mappings), so each test failed for the right reason before the screen code: T6.1 17 of 45 selected tests red, T6.2 24 of 24 red, T6.3 19 of 25 red (the other six were the three `RunRefreshTest` cases, which assert shared behaviour that already exists, and three large-text cases of earlier screens). The screens and tests were then written to green in the same step; screenshots were recorded after the behaviour tests passed and each baseline image was looked at.
- **Tab roots and selection.** Factory home and Agents wait for the app holder's selection (`rememberSelection`) instead of using the throwing `selection()`; tiles use a new defaulted `TabNavigator.select`. Pushed `Agent` and `Run` routes replace their placeholders; `Issue` is still a placeholder until 2a-7 (current issue and the run viewer's issue line push `AppRoute.Issue`).
- **Plurals.** Android Lint (`PluralsCandidate`, warnings as errors) rejects `%d running` as a plain string: counts with words are `<plurals>` with identical one and other text where English has no difference; the percent strings keep `%%`.
- **Run viewer.** The log panel's scroll position is the only Compose state; a drag is told from a programmatic scroll by the scroll state's interaction source. Robolectric `swipeDown` raises the drag interaction, so the "user scrolled up" intent is tested. The cancel bar is outside the page scroll, so tests tap it without `performScrollTo` (which fails without a scrollable ancestor). `performTextInput` appends, so replacing a typed amount uses `performTextReplacement`.
- **Criterion 8 in virtual time.** The holders use `Dispatchers.Default` (`newScreenScope()`), so only the refresh policy runs in virtual time (`TestScope`); the holder's work is awaited in real time. Cancelling sets the run to Cancelled from the use case's response, so the test proves "Cancelled before any virtual time passes, still Cancelled one cycle later, no timer after", not that the policy notices a cancel made on another device.
- **Proof gaps in shared (not changed).** `DemoControls` has no pause, cancel, run-now or set-budget counters, so a declined prompt is proven by the prompt count, the unchanged status and the feedback banner, and an approved one by the visible change; no control to make the server cancel or finish a run on its own, so the policy noticing an external cancel is not proven; the demo has no Viewer membership (viewer and operator variants are built states); the holders do no dispatcher injection (real-time waits); `RunViewerState` and `AgentsState` have no `isRefreshing`, so pull to refresh has no spinner on Agents and the Run viewer has no pull to refresh; the "View run replaces Run now" rule is in the app (`AgentRowUi.visibleActions`) as on iPhone and belongs in the holder; the iPhone factory switcher line is not ported.

## 2a-7 notes

- **Process (red first).** Every task started with its tests and a stub that compiled and rendered nothing (or threw `TODO()` for the label mappings): T7.1 18 of 42 selected tests red, T7.2 25 of 25 red, T7.3 21 of 23 red (the other two, "https only refuses" and "nothing can show the page", are true of the stub's constant `false` by construction). `WorkLargeTextTest` and `WorkScreenshotTest` are characterisation tests written after the screens and passed on their first run; the baselines were each looked at.
- **Layout bug found by the live-graph test, not the stateless one.** The Work list's count row put the count column and the New issue button in an `AdaptiveRow`; with a real `UpdatedLabel` (full width) the button got zero width, so a tap did nothing. The stateless test (no `updatedAt`) passed. It now uses `ActionRow` (weights, stacked at font scale 1.3 and above). Lesson: every screen needs at least one test through the real holder with demo values, and the first assertion on a button should be that it has a size.
- **Semantics pitfalls.** A node that merges its descendants is a boundary: pills (`StatusPill`) and `selectable` choice rows do not contribute their text to a parent that merges, so the Work row is cleared and given one sentence (`clearAndSetSemantics`), and tests read `contentDescription` for a row. `assertContentDescriptionContains` matches a whole list entry, not a substring. `performTextInput` inserts at the cursor (the start of a field that was given its text programmatically): use `performTextReplacement` to extend an existing value.
- **Sheet timing.** A bottom sheet is not displayed at the moment the tap returns: the holders answer on `Dispatchers.Default` and a recomposition mid-slide made `assertIsDisplayed` fail intermittently in the full run (twice, on two different `ApprovalScreenTest` cases that passed alone). `ComposeTestRule.awaitDisplayed(tag)` waits for the node; the seven immediate assertions on `note-sheet`, `confirm-destructive-sheet` and `agent-budget-form` in the existing tests use it now.
- **Demo values.** PAP-1204 "Add retries to webhook ingest" (Blocked, High, Engineer 1; project "Billing v2") has two comments, the plan, three runs, two files and Engineer 1's two questions; PAP-1182 "Billing v2" has four subtasks, a plan and the CTO's live run (so its Runs tab is not empty: the empty-tab test uses PAP-1186). The demo has no request of the other four kinds and no unsupported one, so those are drawn from built `InteractionUi` values (`interactionCard(...)` fixture), as the viewer and offline variants are.
- **Proof gaps in shared (not changed).** (1) No port for attachment bytes (ADR-064): files cannot be opened (reported). (2) `DemoControls` has no way to make a comment, a create or a respond fail, so "a failed comment comes back into the box" is proven by a refusal through the real holder (`BodyRequired` on a blank comment keeps the text) plus a stateless test that gives the content a `Failed` feedback and an unchanged `commentSentCount`; `FakeIssueGateway.failures` exists but is not reachable from the app. (3) No respond or comment call counters in `DemoControls`; "answer sent once" is proven by the card reading Answered and the Inbox feed. (4) No Viewer membership in the demo (viewer variants are built states). (5) `IssueState` and `WorkListState` have no `isRefreshing`, so pull to refresh shows no spinner. (6) The Issue's identifier and project line, the "Part of" and "Blocked by" labels and the tab counts ("Runs 3" only after a tab has been read) follow the iPhone; the mock shows the counts at once. (7) The iPhone factory switcher line is not ported (the Factories tab switches). (8) No inline markdown on Android (the iPhone's `AttributedString`); comment and plan text is plain.
- **App-side rules kept to a minimum.** Colour per status and priority, the chip order and the https-only web door. Nothing decides what is allowed, what is valid or who may answer. No shared-core gap beyond those listed.

## Edge cases and solutions

- T0.4: with `warningsAsErrors` Android Lint flagged `NewerVersionAvailable` (it reads the root catalog), `DataExtractionRules` (needs `fullBackupContent` for API 28 to 30), `MissingApplicationIcon` and `UnusedResources`. Fixed with `androidApp/lint.xml` (version-currency checks ignored: Dependabot owns them), `backup_rules.xml` and a placeholder adaptive icon (final artwork in T8.3). The planted `Planted.kt` (unformatted, unused private member) and `layout/planted.xml` (`android:text="Hello"`) failed spotless, detekt (once `androidApp/src` joined its source set) and lint `HardcodedText` before being removed.
- T0.4 also found detekt issues in the T0.3 Konsist test (complexity, function count); the XML scanning moved to `ManifestScanning.kt`. T0.3 had only run konsistTest and assemble, not detekt: always run the whole gate set per task.

## Deviations from plan

- T1.2: protected-key window instead of per-use, API 30 minimum for protected keys (see Technical decisions, ADR-123).
- T1.6: the Konsist rule no longer bans `java.io` in `securestore` outright; it allows it in `RecordFiles.kt` only.
- Device tests of T1.3 and T1.4 (and the Keystore parts of T1.2 beyond the contract) were written after the implementation they check; their host-side counterparts were red first. T1.5's device test was red first and found the framework bug.

## Lessons learned

- Run `konsistTest` and `detekt` after every task, not only the tests of the module touched: detekt's default test excludes do not cover `androidHostTest` or `androidDeviceTest` (MagicNumber, TooManyFunctions), so those tests use named constants and small classes.
- An emulator test found a real bug in T1.5 that no JVM test could: the Android SQLite framework replaces a corrupt database silently.
- Tool sandboxes in this repository refuse compound shell commands in the worktree; use the Write/Edit tools or plain commands.
