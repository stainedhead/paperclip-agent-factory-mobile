# Implementation notes: Phase 2a Android UI

**Date:** 2026-11-04

Record decisions, edge cases, deviations and lessons as the work lands, with commit hashes. Update after every task (same rule as `status.md`).

## Technical decisions

- **Research Q5 resolved (T0.1/T0.2): AGP 9.5.0 built-in Kotlin needs no extra Kotlin plugin.** `:androidApp` applies only `com.android.application` (through the `pafm.android-app` convention plugin in `build-logic`) plus `org.jetbrains.kotlin.plugin.compose`; `src/main/kotlin` is compiled by AGP's built-in Kotlin (task `compileDebugKotlin`, output under `build/intermediates/built_in_kotlinc`). `org.jetbrains.kotlin.android` is not applied. The Compose compiler plugin does require the Compose runtime on the classpath (the build failed with `IncompatibleComposeRuntimeVersionException` until `compose-runtime` was added), so the module depends on the BOM and the runtime from the start.
- SDK constants (`compileSdk` 37, `minSdk` 28, namespace root) live in `build-logic/src/main/kotlin/PafmAndroid.kt` and are used by both `pafm.kmp-library` and `pafm.android-app` (T0.1 refactor step). `targetSdk` equals `compileSdk`.
- **Catalog (T0.2).** Latest stable versions that resolve (checked by resolving every entry in a throwaway configuration, 141 artifacts): Compose BOM 2026.09.00; activity-compose 1.13.0; navigation-compose 2.10.2; lifecycle (viewmodel/runtime-compose, process) 2.11.0; biometric 1.1.0 (1.4.0-alpha07 exists, alpha not taken); browser 1.10.0; core-splashscreen 1.2.0; core-ktx 1.19.1; profileinstaller 1.4.1; androidx.test runner 1.7.0, core 1.7.0, ext-junit 1.3.0; Roborazzi 1.77.0; Robolectric 4.17; JUnit 4.13.2; junit-vintage-engine 6.1.3 (same version as the pinned `junit` 6.1.3, so a Vintage engine exists for the pinned JUnit platform: research Q6 sub-question answered). `CatalogRulesTest` (Konsist) fails on any literal dependency or plugin version in a `*.gradle.kts` (settings foojay plugin excepted).
- **Research Q2 resolved (T0.7): `withDeviceTest` DSL.** In `pafm.kmp-library`, inside `extensions.configure<KotlinMultiplatformAndroidLibraryTarget>("android") { ... }`: `withDeviceTest { instrumentationRunner = "androidx.test.runner.AndroidJUnitRunner" }`. It creates the source set `androidDeviceTest` and the tasks `assembleAndroidDeviceTest` and `connectedAndroidDeviceTest`. The convention enables it only for modules that have `src/androidDeviceTest` (securestore, platform, persistence, umbrella), so the other modules gain no variant. Dependencies are added with `sourceSets.matching { it.name == "androidDeviceTest" }.configureEach { dependencies { ... } }`: kotlin-test, androidx.test runner/core/ext-junit, coroutines-test. `check` has no `connected*` task in its graph (verified with `./gradlew check lint --dry-run`).
- **Device test method names cannot contain spaces.** D8 rejects backticked names with spaces for minSdk 28 (DEX 039: "Space characters in SimpleName ... not allowed prior to DEX version 040"), so device and instrumented tests use camelCase names; `commonTest`, host tests and JVM tests keep sentence names. Applies to `androidApp/src/androidTest` too.
- **Research Q6 resolved (T0.8), ADR-121.** JUnit Vintage engine 6.1.3 exists for the pinned JUnit 6.1.3 platform and works: `PureJvmSmokeTest` (JUnit 5), `ComposeSmokeTest` and `RoborazziSmokeTest` (JUnit 4 + Robolectric, `createComposeRule`) all run in one `:androidApp:testDebugUnitTest` (3 tests, 0 failures). The fallback (JUnit 4 throughout) is not needed. Needed to make Robolectric run: `--add-opens=java.base/java.io=ALL-UNNAMED` and `--add-exports=java.base/jdk.internal.access=ALL-UNNAMED` on the test JVM; `robolectric.properties` `sdk=36` (Robolectric 4.17 has no API 37 android-all, failing with `NoSuchMethodException InputManager.getInstance()`); compose-ui and compose-foundation as app (not test-only) dependencies (else `NoClassDefFoundError androidx/customview/poolingcontainer/R$id`). Roborazzi: `verifyRoborazziDebug` with no baseline fails ("original file ... was not found"), `recordRoborazziDebug` writes `src/test/screenshots/smoke.png`, `verifyRoborazziDebug` then passes.
- **Research Q (undecryptable record) resolved (T1.1, T1.2), ADR-123.** A record that does not decrypt under a healthy key, a missing key, a truncated or foreign file all read as `Missing`; only `KeyPermanentlyInvalidatedException` is `Invalidated`; any other Keystore failure is `Denied`. Verified on the host with `FakeKeystoreBackend` and on the Pixel 9 Pro emulator (flipped and truncated bytes, key deleted).
- **Protected keys use a 5 second authorization window, not per-use (T1.2).** `setUserAuthenticationParameters(5, STRONG | CREDENTIAL)` (API 30+) with the store asking the injected authenticator first; per-use needs a `CryptoObject` bound to the prompt and would put the activity inside `securestore`. Below API 30 a protected write fails (no deprecated API, no fallback to unprotected).
- **`KeystoreSecretStore(context, authenticate, writeReason)`** takes the prompt as `suspend (String) -> BiometricResult`; 2a-2 wires it to `BiometricPromptBiometrics` (a small adapter in the umbrella). `BiometricPromptBiometrics` takes `ReasonTexts` (moved from iosMain to commonMain), so the prompt title is the app's localized text.
- **Emulator facts (T1.2, T1.4).** `svc`/`cmd connectivity airplane-mode enable|disable` from `UiAutomation.executeShellCommand` flips the default network and the callback reports it within a second or two; the library test APK needs its own `src/androidDeviceTest/AndroidManifest.xml` for `ACCESS_NETWORK_STATE`. Removing the lock screen (`adb shell locksettings clear --old 1234`) deletes user-authentication keys on this emulator (API 37) rather than invalidating them. The two-phase run is `KeystoreInvalidationDeviceTest` with `-e invalidationPhase 1|2` through `adb shell am instrument` (set PIN, phase 1, clear PIN, phase 2).
- **Manifest rule (T1.3).** `androidx.biometric` 1.1.0 adds `USE_FINGERPRINT`: removed with `tools:node="remove"` (minSdk 28). `androidx.profileinstaller`'s exported `ProfileInstallReceiver` (from Compose; the rule was already red at the start of 2a-1) removed; `androidx.activity.ComponentActivity` from `ui-test-manifest` allowed in the debug manifest only. T8.6 re-adds the receiver for the benchmark build type in review.

## 2a-4 notes

- Live-graph emulator check used `adb shell locksettings set-pin 1234` (demo extra for screens; PIN set so the live graph can open).
- Demo values: Cloud factory is SignedOut with an expired key, so it reads "Key expired" (as in the mock), only Test factory reads "Signed out".
- Gaps in shared (not changed): the demo graph binds `FakePairingBrowser` and takes no browser, so the edit screen's re-pair cannot be proven end to end through the Custom Tab launcher (covered separately by `CustomTabsPairingBrowserTest` and `PairingRoutingTest`); `DemoControls` has no delete counter (cancelled prompt is proven by prompt count and an unchanged list); no source for server compatibility or Keystore error classes (Not recorded); the demo `listKeys` answers every factory alike.
- Holder-fed text fields keep typed text locally and tests wait a moment before asking the holder what it made of it.

## Edge cases and solutions

- T0.4: with `warningsAsErrors` Android Lint flagged `NewerVersionAvailable` (it reads the root catalog), `DataExtractionRules` (needs `fullBackupContent` for API 28 to 30), `MissingApplicationIcon` and `UnusedResources`. Fixed with `androidApp/lint.xml` (version-currency checks ignored: Dependabot owns them), `backup_rules.xml` and a placeholder adaptive icon (final artwork in T8.3). The planted `Planted.kt` (unformatted, unused private member) and `layout/planted.xml` (`android:text="Hello"`) failed spotless, detekt (once `androidApp/src` joined its source set) and lint `HardcodedText` before being removed.
- T0.4 also found detekt issues in the T0.3 Konsist test (complexity, function count); the XML scanning moved to `ManifestScanning.kt`. T0.3 had only run konsistTest and assemble, not detekt: always run the whole gate set per task.

## Deviations from plan

- T1.2: protected-key window instead of per-use, API 30 minimum for protected keys (see Technical decisions, ADR-123).
- T1.6: the Konsist rule no longer bans `java.io` in `securestore` outright; it allows it in `RecordFiles.kt` only.
- Device tests of T1.3 and T1.4 (and the Keystore parts of T1.2 beyond the contract) were written after the implementation they check; their host-side counterparts were red first. T1.5's device test was red first and found the framework bug.

## Lessons learned

- Run `konsistTest` and `detekt` after every task, not only the tests of the module touched: detekt's default test excludes do not cover `androidHostTest` or `androidDeviceTest` (MagicNumber, TooManyFunctions), so those tests use named constants and small classes.
- An emulator test found a real bug in T1.5 that no JVM test could: the Android SQLite framework replaces a corrupt database silently.
- Tool sandboxes in this repository refuse compound shell commands in the worktree; use the Write/Edit tools or plain commands.
